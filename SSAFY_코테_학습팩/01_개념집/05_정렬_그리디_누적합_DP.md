# 정렬, 그리디, 누적합, DP 기초

이 장에서는 공식뿐 아니라 각 변수에 어떤 의미의 값이 들어가는지 확인합니다. `prefix`, `dp`는 파이썬 명령이 아니라 작성자가 정한 리스트 이름입니다.

## 1. 정렬 후 처리

정렬은 값을 정한 기준으로 늘어놓아 이후 판단을 쉽게 합니다. 작은 것부터 고르거나, 시간 순서대로 처리하거나, 같은 값들을 모을 때 사용합니다.

```python
arr = [30, 10, 20]
arr.sort()
print(arr)  # [10, 20, 30]
```

`arr`는 데이터 목록입니다. `.sort()`는 원본을 바꾸고 `None`을 반환합니다. `sorted(arr)`는 새 정렬 리스트를 반환합니다. 문자열 정렬은 `"".join(sorted(s))`를 사용합니다. 기초 문법은 2장에 있습니다.

### 복합 기준을 풀어서 읽기

각 항목이 `(가격, 품질)`일 때, 가격 오름차순·동점이면 품질 내림차순으로 정렬해 봅니다.

```python
items = [(100, 3), (50, 2), (100, 5)]

def item_key(item):
    price = item[0]
    quality = item[1]
    return (price, -quality)

items.sort(key=item_key)
print(items)  # [(50, 2), (100, 5), (100, 3)]
```

- `items`는 항목 전체, `item`은 정렬 기준을 구할 항목 하나입니다.
- `price`, `quality`는 그 항목의 가격과 품질입니다.
- `key`에는 각 항목의 비교 기준을 만드는 함수를 전달합니다.
- 기준 튜플 `(가격, -품질)`을 앞에서부터 비교합니다. 가격이 같을 때만 두 번째 값을 비교합니다.
- 원래 품질이 5이면 -5, 3이면 -3이므로 작은 값부터 놓아도 높은 품질이 먼저 옵니다.

축약형은 `items.sort(key=lambda x: (x[0], -x[1]))`입니다. `lambda x: 식`은 x를 받아 식을 반환하는 짧은 함수이며, 여기서 x는 항목 튜플 하나입니다. 문자열에는 음수 부호를 붙일 수 없으므로 `-x[1]`은 해당 값이 숫자라는 전제입니다.

## 2. 그리디: 지금 선택이 최종 답에도 유리한가?

그리디는 매 단계에서 정한 기준상 가장 유리한 선택을 하는 방법입니다. 핵심은 '지금 좋아 보인다'가 아니라 **그 선택을 해도 최적의 답을 놓치지 않는 이유**가 있어야 한다는 것입니다.

### 큰 단위부터 거스름돈 계산

다음 화폐 단위에서, 10의 배수인 음수 아닌 금액을 최소 개수로 거슬러 준다고 가정합니다. 각 화폐는 무제한 있습니다.

```python
money = 1260
coins = [500, 100, 50, 10]
answer = 0
for coin in coins:
    count = money // coin
    money %= coin
    answer += count
    print(coin, count, money)
print("총 개수", answer)
```

출력:

```text
500 2 260
100 2 60
50 1 10
10 1 0
총 개수 6
```

| 변수 | 의미 |
|---|---|
| `money` | 아직 거슬러 줘야 할 남은 금액. 처음 1260 |
| `coins` | 사용할 화폐 단위를 큰 순서대로 담은 리스트 |
| `coin` | 이번에 처리하는 단위 |
| `count` | 그 단위를 사용할 개수 |
| `answer` | 지금까지 사용한 화폐의 총 개수 |

`money // coin`은 몫입니다. `1260 // 500 = 2`이므로 500을 두 개 씁니다. `money %= coin`은 `money = money % coin`의 축약형으로, 나머지 260만 남깁니다.

이 단위들은 큰 단위가 바로 아래 단위의 정수 배수입니다. 같은 금액의 작은 화폐 여러 개는 큰 화폐 하나로 바꾸는 것이 개수를 줄이므로 큰 단위를 먼저 쓰는 방법이 성립합니다. 최소 단위로 표현할 수 없는 금액이라면 마지막 money가 0이 되지 않을 수 있습니다.

**화폐 단위가 임의이면 이 방법이 틀릴 수 있습니다.** 단위가 `[4, 3, 1]`, 금액이 6이면 큰 것부터는 `4+1+1`로 3개이지만 최적은 `3+3`으로 2개입니다.

### 회의 선택도 기준의 이유가 필요

회의실 하나에서 최대한 많은 회의를 진행하려면 보통 종료 시간이 빠른 회의부터 선택합니다. 먼저 시작하는 회의를 고르면 긴 회의 하나가 뒤의 여러 회의를 막을 수 있습니다. 가장 빨리 끝나는 회의를 선택하면 뒤에 남는 시간을 줄이지 않는다는 교환 논리를 사용할 수 있습니다. 이때 한 회의의 종료와 다음 회의 시작이 같아도 되는지는 문제 조건을 확인합니다.

그리디가 의심되면 작은 반례부터 만들어 보고, 안 되는 경우에는 완전탐색이나 DP를 검토합니다.

## 3. 1차원 누적합: 앞부분의 합을 저장

누적합은 앞에서부터 쌓은 합입니다. 구간 합을 여러 번 묻는 문제에서 매번 구간 전체를 더하지 않도록 합니다.

이 장의 약속은 **prefix[k] = arr의 앞 k개 합**입니다. 따라서 `prefix[0] = 0`이고, `prefix[1]`에 arr의 첫 값이 들어갑니다.

```python
arr = [3, 1, 4, 2, 5]
N = len(arr)
prefix = [0] * (N + 1)
for i in range(N):
    prefix[i + 1] = prefix[i] + arr[i]

l = 1
r = 3
section = prefix[r + 1] - prefix[l]
print(prefix)   # [0, 3, 4, 8, 10, 15]
print(section)  # 7
```

| 변수 | 의미 |
|---|---|
| `arr` | 원래 값 목록 |
| `N` | 값 개수. 여기서는 5 |
| `i` | 지금 누적합에 추가할 값의 인덱스 |
| `prefix` | 앞 k개 합을 k번 칸에 저장한 길이 N+1 리스트 |
| `l` | left. 합을 구할 시작 인덱스. 소문자 L |
| `r` | right. 합을 구할 마지막 인덱스. 이 절에서는 행이 아님 |
| `section` | 해당 구간의 합 |

`0 <= l <= r < N`인 구간이고 양쪽 끝을 모두 포함한다고 가정합니다. 같은 r이라는 이름이라도 3장의 row와 이 절의 right는 뜻이 다릅니다.

| k | prefix[k]에 들어 있는 합 | 값 |
|---:|---|---:|
| 0 | 아무것도 더하지 않음 | 0 |
| 1 | 3 | 3 |
| 2 | 3+1 | 4 |
| 3 | 3+1+4 | 8 |
| 4 | 3+1+4+2 | 10 |
| 5 | 3+1+4+2+5 | 15 |

`arr[1]~arr[3]`의 합은 `1+4+2 = 7`입니다. arr[3]까지의 합 `prefix[4] = 10`에서 arr[1] 직전까지의 합 `prefix[1] = 3`을 뺍니다.

```text
prefix[r+1] = arr[0] + ... + arr[l-1] + arr[l] + ... + arr[r]
prefix[l]   = arr[0] + ... + arr[l-1]
빼고 남는 것: arr[l] + ... + arr[r]
```

누적합을 만드는 데 O(N), 그 뒤 구간 합 하나는 O(1)입니다. 질문이 Q개이면 총 O(N+Q)입니다. Q는 구간 합을 묻는 횟수입니다. 원본 값이 바뀌면 기존 prefix도 맞지 않게 된다는 점을 기억합니다.

## 4. 2차원 누적합: 왼쪽 위 직사각형의 합

이 절부터 다시 r은 행, c는 열입니다. N은 행 수, M은 열 수입니다.

약속: **prefix[a][b]는 board의 앞 a개 행, 앞 b개 열로 이루어진 왼쪽 위 직사각형의 합**입니다. 즉 원본 행 0~a-1, 열 0~b-1의 합입니다. a 또는 b가 0이면 합은 0입니다.

```python
board = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9],
]
N = len(board)
M = len(board[0])
prefix = [[0] * (M + 1) for _ in range(N + 1)]

for r in range(N):
    for c in range(M):
        prefix[r + 1][c + 1] = (
            prefix[r][c + 1]
            + prefix[r + 1][c]
            - prefix[r][c]
            + board[r][c]
        )

def rect_sum(r1, c1, r2, c2):
    return (
        prefix[r2 + 1][c2 + 1]
        - prefix[r1][c2 + 1]
        - prefix[r2 + 1][c1]
        + prefix[r1][c1]
    )

print(rect_sum(1, 1, 2, 2))  # 28: 5+6+8+9
```

| 이름 | 의미 |
|---|---|
| `board` | 원본 격자 |
| `N`, `M` | 원본 행 수와 열 수 |
| `prefix` | 위에 0행, 왼쪽에 0열을 덧붙인 누적합 격자 |
| `r`, `c` | 지금 누적합에 반영할 원본 칸의 인덱스 |
| `r1`, `c1` | 합을 구할 직사각형의 왼쪽 위 좌표 |
| `r2`, `c2` | 합을 구할 직사각형의 오른쪽 아래 좌표. 포함 |
| `rect_sum` | rectangle sum. 사각형 합을 반환하는 함수 이름 |

전제는 `0 <= r1 <= r2 < N`, `0 <= c1 <= c2 < M`입니다. prefix의 첫 행과 첫 열을 0으로 두면 가장자리에서도 음수 인덱스 없이 같은 공식을 사용할 수 있습니다.

### 만들 때는 위 + 왼쪽 - 겹친 부분 + 현재 값

`prefix[r][c+1]`은 현재 칸 위쪽까지의 합이고, `prefix[r+1][c]`는 왼쪽까지의 합입니다. 둘을 더하면 왼쪽 위의 `prefix[r][c]`가 두 번 포함됩니다. 한 번 빼고 현재 칸 `board[r][c]`를 추가합니다.

예를 들어 원본의 값 5까지 반영할 때 r=1, c=1입니다.

```text
prefix[2][2] = prefix[1][2] + prefix[2][1] - prefix[1][1] + board[1][1]
             = 3 + 5 - 1 + 5
             = 12
```

완성한 prefix는 다음과 같습니다.

```text
0   0   0   0
0   1   3   6
0   5  12  21
0  12  27  45
```

### 물어볼 때는 전체 - 위 - 왼쪽 + 겹친 부분

원하는 직사각형의 오른쪽 아래까지 큰 합을 잡고, 불필요한 위쪽과 왼쪽을 뺍니다. 두 번 뺀 왼쪽 위 영역은 한 번 더합니다.

```text
rect_sum(1, 1, 2, 2)
= prefix[3][3] - prefix[1][3] - prefix[3][1] + prefix[1][1]
= 45 - 6 - 12 + 1
= 28
```

누적합 준비는 시간·공간 O(N×M), 직사각형 질문 한 번은 O(1)입니다. 원본 격자 값이 바뀌지 않는 상황에서 여러 질문을 처리할 때 유용합니다.


## 5. DP: 작은 문제의 답을 저장하고 다음 답을 만들기

DP는 Dynamic Programming, 동적 계획법의 약자입니다. 이름만으로 이해하기보다는 '이미 구한 작은 상태의 답을 저장해서 큰 상태의 답을 계산한다'고 생각합니다. 재귀의 같은 계산을 저장하는 방식도 있고, 이 장처럼 작은 인덱스부터 표를 채우는 방식도 있습니다.

`dp`는 보통 답을 저장할 리스트 이름입니다. 특별한 파이썬 문법은 아닙니다. **dp의 각 칸이 무엇을 뜻하는지 문제마다 직접 정의해야 합니다.**

작성 순서:

1. 상태: `dp[i]` 또는 `dp[r][c]`가 어떤 답인가?
2. 초기값: 이전 답 없이 직접 알 수 있는 칸은 무엇인가?
3. 점화식: 어떤 이전 칸들로 현재 칸을 계산하는가?
4. 계산 순서: 참고할 이전 칸들이 먼저 계산되어 있는가?
5. 최종 답: 어느 칸을 출력해야 하는가?

점화식은 '이전 값으로 다음 값을 계산하는 규칙'을 뜻합니다.

### 피보나치: dp[i] = i번째 수

피보나치는 0번째가 0, 1번째가 1이고, 그다음부터 바로 앞 두 수를 더하는 수열입니다.

```python
N = 7
dp = [0] * (N + 1)
if N >= 1:
    dp[1] = 1
for i in range(2, N + 1):
    dp[i] = dp[i - 1] + dp[i - 2]
print(dp)     # [0, 1, 1, 2, 3, 5, 8, 13]
print(dp[N])  # 13
```

- `N`은 구할 피보나치 수의 번호입니다. 0 이상의 정수라고 가정합니다.
- `i`는 지금 구할 수의 번호입니다.
- `dp`는 0번부터 N번까지 저장하므로 길이가 N+1입니다.
- `dp[0] = 0`, `dp[1] = 1`은 문제에서 정한 시작값입니다. N=0일 때는 1번 칸이 없으므로 조건문이 필요합니다.
- `dp[i-1]`, `dp[i-2]`는 이미 계산한 바로 앞 두 수입니다.

| i | 계산 | dp[i] |
|---:|---|---:|
| 2 | 1+0 | 1 |
| 3 | 1+1 | 2 |
| 4 | 2+1 | 3 |
| 5 | 3+2 | 5 |
| 6 | 5+3 | 8 |
| 7 | 8+5 | 13 |

반복 횟수는 O(N), 저장하는 칸 수도 O(N)입니다. 보통의 코딩 테스트 복잡도 설명에서는 각 정수 연산을 일정 비용으로 보지만, 매우 큰 N에서는 정수의 자릿수도 커진다는 점은 별도 고려합니다.

### 격자 최대 합: dp[r][c] = 그 칸까지 오는 최대 합

규칙은 다음과 같습니다.

- 왼쪽 위 `(0, 0)`에서 오른쪽 아래 `(N-1, M-1)`까지 갑니다.
- 한 번에 오른쪽 또는 아래로 한 칸 이동합니다.
- 지나간 모든 칸의 값을 더하며 시작·도착 칸도 포함합니다.
- 벽은 없고 모든 칸을 지날 수 있습니다. N과 M은 1 이상입니다.

```python
board = [
    [1, 2, 3],
    [4, 5, 6],
]
N = len(board)
M = len(board[0])
dp = [[0] * M for _ in range(N)]
dp[0][0] = board[0][0]

for c in range(1, M):
    dp[0][c] = dp[0][c - 1] + board[0][c]

for r in range(1, N):
    dp[r][0] = dp[r - 1][0] + board[r][0]

for r in range(1, N):
    for c in range(1, M):
        dp[r][c] = max(dp[r - 1][c], dp[r][c - 1]) + board[r][c]

for row in dp:
    print(row)
print("최대 합", dp[N - 1][M - 1])
```

출력:

```text
[1, 3, 6]
[5, 10, 16]
최대 합 16
```

| 변수 또는 식 | 뜻 |
|---|---|
| `board` | 각 칸에서 얻는 원래 값 |
| `N`, `M` | 행 수, 열 수 |
| `r`, `c` | 지금 답을 구할 칸의 인덱스 |
| `dp[r][c]` | 시작점부터 이 칸까지 올 수 있는 경로 중 최대 합 |
| `dp[r-1][c]` | 바로 위 칸까지의 최대 합 |
| `dp[r][c-1]` | 바로 왼쪽 칸까지의 최대 합 |
| `row` | 출력할 dp의 한 행 |

현재 칸으로 올 수 있는 직전 위치는 위 또는 왼쪽뿐입니다. 둘 중 더 큰 경로 합을 골라 현재 칸 값을 더합니다. 다른 방향의 이동을 허용하면 이 점화식도 다시 검토해야 합니다.

계산 과정을 값 5인 칸 `(1, 1)`로 보면:

```text
위에서 오는 최대 합: dp[0][1] = 3
왼쪽에서 오는 최대 합: dp[1][0] = 5
현재 값: board[1][1] = 5
따라서 dp[1][1] = max(3, 5) + 5 = 10
```

최종 칸은 `max(6, 10) + 6 = 16`입니다. 한 최적 경로는 `1 → 4 → 5 → 6`입니다.

### 왜 첫 행과 첫 열을 따로 채울까?

첫 행은 왼쪽에서만 올 수 있고, 첫 열은 위에서만 올 수 있습니다. 이 실제 경로의 합으로 채워야 음수 값이 있어도 맞습니다.

예를 들어 board가 `[[-1, -2], [-3, -4]]`이면 올바른 dp는 `[[-1, -3], [-4, -7]]`이고 답은 -7입니다. 초기 0과 실제 음수 경로를 `max()`로 비교하면 존재하지 않는 0점 경로가 선택될 수 있습니다. 위 코드는 경계의 실제 경로부터 계산하므로 이 문제가 없습니다.

칸마다 일정한 수의 이전 값을 비교하므로 시간 O(N×M), dp 공간 O(N×M)입니다. 이 코드는 최대 합만 저장하며 실제 경로를 출력하려면 어느 이전 칸을 골랐는지도 추가로 기록해야 합니다.

## 6. 누적합과 DP가 헷갈릴 때

두 방식 모두 이전 값을 이용하지만 저장하는 값과 목적을 구분합니다.

| 방법 | 이 장에서 저장한 값 | 사용하는 이유 |
|---|---|---|
| 누적합 | 정해진 앞부분 전체의 합 | 여러 구간 합을 빠르게 계산 |
| 피보나치 DP | 각 번호의 피보나치 수 | 같은 하위 계산을 반복하지 않기 |
| 경로 DP | 각 칸까지 가능한 경로 중 최대 합 | 모든 경로를 직접 나열하지 않고 최적값 계산 |

이전 값을 사용한다는 공통점만 보고 이름을 정하기보다, 내 리스트의 각 칸이 정확히 어떤 답인지 문장으로 적습니다.

## 7. 실전 판단과 조건 확인

| 질문 | 검토할 방법 | 확인할 조건 |
|---|---|---|
| 정해진 규칙을 그대로 따라가면 되는가? | 구현·시뮬레이션 | 동시 변화인지 순차 변화인지 |
| 지금의 선택이 항상 최적해로 이어지는가? | 그리디 | 선택이 맞는 이유와 반례 |
| 같은 원본의 구간 합을 여러 번 묻는가? | 누적합 | 원본 값이 중간에 바뀌는지 |
| 작은 상태의 답으로 큰 상태의 답을 만들 수 있는가? | DP | 상태 정의·점화식·초기값·계산 순서 |
| 경우의 수가 충분히 작은가? | 완전탐색 | 후보 수 × 후보 하나의 처리량 |
| 답이 될 수 없는 선택을 일찍 버릴 수 있는가? | 백트래킹 | 버리는 조건이 실제로 안전한지 |

문제 이름만 보고 방법을 고르지 않습니다. 입력 크기와 규칙을 먼저 적고, 작은 예시의 예상 답을 손으로 구한 뒤 코드와 비교합니다.
