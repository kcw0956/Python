# 시간복잡도와 입력 크기 완전기초

이 폴더는 코딩 테스트 문제를 읽었을 때 `이 풀이가 시간 안에 돌아갈까?`를 판단하는 법을 익히기 위한 자료입니다.

처음에는 시간복잡도가 수학처럼 느껴질 수 있지만, 실전에서는 어렵게 쓰지 않습니다. 핵심은 딱 하나입니다.

> 입력이 커질 때 내 코드의 반복 횟수가 얼마나 빨리 늘어나는가?

## 읽는 순서

1. `01_입력크기란.md`
   - 문제에서 `N`, `M`, `T`가 무엇인지 읽는 법
2. `02_시간복잡도_빅오.md`
   - O(1), O(N), O(N^2), O(2^N) 같은 표현의 의미
3. `03_반복문_복잡도_계산법.md`
   - 내 코드가 몇 번 도는지 세는 법
4. `04_입력크기별_풀이선택표.md`
   - N이 몇일 때 어떤 풀이를 써야 하는지
5. `05_코테_패턴별_판단법.md`
   - 완전탐색, BFS, DFS, DP, 누적합 선택 기준
6. `06_판단연습문제.md`
   - 직접 풀이법을 고르는 연습
7. `complexity_examples.py`
   - 반복문 모양별 시간복잡도 예시 코드

## 목표

- 입력 크기를 보고 O(N^2)이 가능한지 판단할 수 있다.
- 중첩 반복문의 시간복잡도를 계산할 수 있다.
- 완전탐색, BFS, DFS, DP, 누적합 중 무엇을 의심해야 하는지 알 수 있다.
- 코드를 치기 전에 풀이가 시간 안에 될지 대략 판단할 수 있다.

## 제일 중요한 기준

Python 코딩 테스트에서는 보통 1초에 아주 단순한 연산 기준으로 대략 1천만 번 안팎을 생각합니다.

정확한 숫자가 중요한 것은 아닙니다. 중요한 것은 아래 감각입니다.

- 1만 번: 매우 여유
- 100만 번: 대체로 여유
- 1천만 번: 조심
- 1억 번: Python에서는 위험
- 10억 번: 거의 불가능

따라서 문제를 읽으면 먼저 이런 질문을 해야 합니다.

> 내 풀이가 대략 몇 번 반복할까?
