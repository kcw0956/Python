# 05. 코테 패턴별 판단법

시간복잡도는 단순히 빠른 코드 자랑이 아닙니다. 문제를 읽고 어떤 풀이 패턴을 쓸지 고르는 도구입니다.

## 1. 완전탐색

모든 경우를 다 보는 방식입니다.

쓸 수 있는 경우:

- 입력 크기가 작다.
- 경우의 수가 명확히 작다.
- 구현이 단순하고 제한 시간 안에 돈다.

예:

```text
N <= 100
모든 두 수의 합을 확인
```

O(N^2) = 1만 번이라 가능.

피해야 하는 경우:

```text
N <= 100000
모든 두 수의 합을 확인
```

O(N^2) = 100억 번이라 불가능.

## 2. 카운팅

값의 범위가 작을 때 씁니다.

예:

```text
점수는 0 이상 100 이하
가장 많이 등장한 점수 찾기
```

이때는 리스트 101칸을 만들면 됩니다.

```python
count = [0] * 101
for score in scores:
    count[score] += 1
```

시간복잡도는 O(N)입니다.

## 3. 정렬

순서가 중요해 보이면 정렬을 의심합니다.

쓸 수 있는 경우:

- 가장 작은 것부터 처리
- 가장 큰 것부터 처리
- 가까운 값끼리 비교
- 회의 시간, 도착 시간, 마감 시간 문제

정렬은 O(N log N)이라 N이 100000이어도 보통 가능합니다.

## 4. 누적합

구간 합을 여러 번 물어보면 누적합입니다.

나쁜 풀이:

```python
for _ in range(Q):
    l, r = map(int, input().split())
    print(sum(arr[l:r + 1]))
```

구간 길이가 길고 Q도 크면 O(NQ)가 됩니다.

좋은 풀이:

```python
prefix = [0] * (N + 1)
for i in range(N):
    prefix[i + 1] = prefix[i] + arr[i]

for _ in range(Q):
    l, r = map(int, input().split())
    print(prefix[r + 1] - prefix[l])
```

전처리 O(N), 질문마다 O(1)입니다.

## 5. BFS

최단거리 문제에서 씁니다.

조건:

- 이동 비용이 모두 같다.
- 한 칸 이동이 1회다.
- 최단 횟수를 묻는다.
- 격자, 그래프에서 퍼져 나간다.

예:

```text
S에서 G까지 최소 이동 횟수
벽은 못 지나감
상하좌우 이동
```

이건 BFS입니다.

시간복잡도는 보통 방문 가능한 칸 수만큼입니다. 격자면 O(NM)입니다.

## 6. DFS

끝까지 파고드는 탐색입니다.

쓸 수 있는 경우:

- 연결된 영역 개수 세기
- 모든 경로 탐색
- 재귀적으로 선택하기
- 백트래킹

최단거리에는 보통 BFS가 더 적합합니다.

## 7. 백트래킹

완전탐색 중 불필요한 가지를 버리는 방식입니다.

쓸 수 있는 경우:

- N이 작지만 경우의 수가 많다.
- 조건을 만족하지 못하는 선택을 중간에 버릴 수 있다.
- 순열, 조합, 부분집합 문제다.

예:

```text
키 합이 B 이상이 되는 최소 차이
```

현재 합이 이미 B 이상이면 더 고를 필요 없이 답을 갱신하고 종료합니다.

## 8. DP

이전 계산 결과를 저장해서 다시 쓰는 방식입니다.

의심할 상황:

- 같은 계산이 반복된다.
- `i번째까지의 최댓값` 같은 표현이 가능하다.
- 선택했을 때와 안 했을 때의 최적값을 쌓아간다.
- 제한 시간 안에 모든 경우를 그대로 보면 너무 많다.

예:

```text
시간 제한 L 안에서 점수 최대
```

0/1 배낭 DP를 생각할 수 있습니다.

## 9. 그리디

매 순간 가장 좋아 보이는 것을 선택하는 방식입니다.

의심할 상황:

- 정렬 후 앞에서부터 처리하면 될 것 같다.
- 가장 큰 단위부터 쓰면 된다.
- 가장 빨리 끝나는 것부터 고르면 된다.

단, 그리디는 항상 맞지 않습니다. 왜 그 선택이 나중에도 손해가 아닌지 설명할 수 있어야 합니다.

## 10. 다익스트라

가중치가 있는 최단거리 문제에서 씁니다.

BFS와 차이:

- BFS: 모든 이동 비용이 같음
- 다익스트라: 이동 비용이 다름, 비용은 음수가 아님

예:

```text
각 칸에 복구 비용이 있고, 목적지까지 최소 비용
```

이건 BFS가 아니라 다익스트라입니다.

## 실전 판단 흐름

문제를 읽고 아래 순서로 생각합니다.

1. 최단거리인가?
   - 이동 비용 같음: BFS
   - 이동 비용 다름: 다익스트라
2. 구간 합 질문이 많은가?
   - 누적합
3. 일부를 선택하는가?
   - N 작음: DFS/백트래킹
   - 제한이 시간/무게: DP 의심
4. 모든 쌍을 보는가?
   - N 작음: 완전탐색
   - N 큼: 정렬, set, 투 포인터
5. 격자인가?
   - 델타 탐색, BFS/DFS, 시뮬레이션

## 핵심 정리

- 입력이 작으면 완전탐색부터 생각한다.
- 입력이 크면 전처리나 자료구조를 생각한다.
- 최단거리는 BFS/다익스트라를 먼저 의심한다.
- 구간 질문이 많으면 누적합이다.
- 선택 문제가 나오면 DFS/백트래킹/DP를 비교한다.
