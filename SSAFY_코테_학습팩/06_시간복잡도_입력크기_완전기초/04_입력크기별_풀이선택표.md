# 04. 입력 크기별 풀이 선택표

이 표는 절대 규칙이 아니라 실전 감각을 잡기 위한 기준입니다.

Python 기준으로 단순 연산 1천만 번 안팎을 조심선으로 잡습니다. 실제 가능 여부는 시간 제한, 코드 형태, 입출력 속도에 따라 달라집니다.

## 한눈에 보는 표

| 입력 크기 | 가능한 풀이 후보 |
|---:|---|
| N <= 8 | 순열 O(N!) 가능할 수 있음 |
| N <= 10 | 백트래킹, 순열, 완전탐색 |
| N <= 20 | 부분집합 O(2^N) 가능할 수 있음 |
| N <= 100 | O(N^3)도 경우에 따라 가능, O(N^2)는 대체로 가능 |
| N <= 1000 | O(N^2) 가능할 때 많음 |
| N <= 10000 | O(N^2)는 위험, O(N log N), O(N) 선호 |
| N <= 100000 | O(N log N), O(N) |
| N <= 1000000 | O(N) 중심 |

## N <= 10

가능한 것:

- 순열
- 조합
- 백트래킹
- 모든 순서 시도

예:

```text
N명의 사람을 순서대로 세울 때 최소 비용
```

순서가 중요하고 N이 10 이하라면 순열을 생각할 수 있습니다.

단, N=10이면 10! = 3,628,800입니다. 테스트케이스가 많거나 계산이 무거우면 가지치기가 필요합니다.

## N <= 20

가능한 것:

- 부분집합
- 선택/미선택 DFS
- 비트마스크

예:

```text
N개 중 일부를 골라 합이 B 이상이 되는 최소 차이
```

각 원소를 고르거나 안 고르면 O(2^N)입니다.

N=20이면 약 1,048,576가지라 해볼 만합니다.

## N <= 100

가능한 것:

- O(N^2)
- 가벼운 O(N^3)
- 플로이드 워셜 같은 삼중 반복
- 2차원 배열 구현

예:

```text
100 x 100 격자에서 모든 칸 확인
```

전체 칸은 1만 개입니다. BFS/DFS/델타 탐색은 충분히 가능합니다.

## N <= 1000

가능한 것:

- O(N^2) 약 100만 번
- 정렬 O(N log N)
- BFS/DFS

조심할 것:

- O(N^3)은 10억 번이라 거의 불가능

예:

```text
모든 쌍 비교
```

N=1000이면 약 100만 쌍입니다. 조건이 단순하면 가능할 수 있습니다.

## N <= 100000

가능한 것:

- O(N)
- O(N log N)
- 정렬
- 해시 set/dict
- 누적합
- 투 포인터
- 이분 탐색

불가능한 것:

- O(N^2)

N=100000에서 O(N^2)은 100억 번입니다.

이때 모든 쌍을 보면 안 됩니다.

## 격자 N x M

격자는 N만 보지 말고 전체 칸 수를 봅니다.

```text
N <= 100, M <= 100
```

전체 칸은 1만 개입니다.

```text
N <= 1000, M <= 1000
```

전체 칸은 100만 개입니다.

BFS 한 번은 가능하지만, 모든 칸에서 BFS를 다시 돌리면 위험합니다.

## Q개의 질문이 있는 경우

예:

```text
N <= 100000
Q <= 100000
```

매 질문마다 O(N)을 하면 O(NQ) = 100억 번입니다.

이때는 전처리를 해야 합니다.

대표 전처리:

- 누적합
- 정렬
- 딕셔너리 카운팅
- DP

## 입력 크기별 대표 패턴

| 상황 | 입력 크기 | 생각할 패턴 |
|---|---:|---|
| 모든 쌍 비교 | N <= 1000 | O(N^2) 가능 |
| 모든 쌍 비교 | N >= 100000 | set, 정렬, 투 포인터 |
| 구간 합 질문 많음 | Q 큼 | 누적합 |
| 최단거리 격자 | N*M <= 1000000 | BFS |
| 가중치 최단거리 | N*M 큼 | 다익스트라 |
| 일부 선택 | N <= 20 | 부분집합 |
| 순서 나열 | N <= 10 | 순열/백트래킹 |
| 격자 전체 변화 | N*M 작음 | 시뮬레이션 |

## 실전에서 이렇게 판단

문제를 읽고 아래처럼 생각합니다.

```text
N이 100000이네?
이중 반복문은 안 되겠다.
정렬, set, 누적합 중 하나를 생각해야겠다.
```

```text
N이 15네?
선택/미선택으로 모든 부분집합을 봐도 될 수 있겠다.
```

```text
N과 M이 100이고 격자네?
전체 칸 10000개라 BFS 한 번은 괜찮겠다.
```

```text
Q가 100000이고 매번 구간 합을 물어보네?
매번 sum 하면 안 되고 누적합이 필요하겠다.
```

## 핵심 정리

- N이 작으면 완전탐색이 강하다.
- N이 크면 모든 경우를 보면 안 된다.
- Q가 크면 전처리를 의심한다.
- 격자는 `N * M`을 본다.
- 테스트케이스가 있으면 `T`까지 곱한다.
