# 시험장 체크리스트

## 문제 읽을 때

- 입력 크기 `N`, `M`, `T`부터 확인합니다.
- 출력 형식이 `#tc answer`인지 일반 출력인지 확인합니다.
- 인덱스가 0부터인지 1부터인지 표시합니다.
- "동시에", "먼저", "반복", "가장 짧은", "최대" 같은 단어에 밑줄을 긋는다고 생각합니다.

## 구현 전

- 완전탐색 가능한지 경우의 수를 계산합니다.
- 2차원 배열이면 `dr`, `dc`가 필요한지 확인합니다.
- 최단거리면 BFS, 모든 경로/선택이면 DFS/백트래킹을 우선 의심합니다.
- 정렬 후 순서대로 처리 가능한지 봅니다.

## 코드 작성 중

- `input = sys.stdin.readline`을 쓸 때 문자열 끝 개행 처리를 조심합니다.
- BFS는 큐에 넣을 때 방문 체크합니다.
- DFS는 재귀 종료 조건을 함수 맨 위에 둡니다.
- 원본 배열을 바꾸는 시뮬레이션이면 복구가 필요한지 확인합니다.
- `sum`, `list`, `dict`, `max` 같은 내장 함수 이름을 변수로 쓰지 않습니다.

## 제출 전

- 샘플 입력을 직접 넣어봅니다.
- 최소 크기, 최대 크기, 전부 0, 전부 1, 같은 값 반복 케이스를 생각합니다.
- 정답이 여러 줄인지 한 줄인지 다시 확인합니다.
- `print(f"#{tc} {ans}")`에서 공백이 맞는지 확인합니다.

## 자주 나는 실수

- `range(N)`과 `range(1, N + 1)` 혼동
- 행과 열을 `r`, `c`가 아니라 `x`, `y`로 섞어 쓰다가 반대로 접근
- 방문 체크를 늦게 해서 큐에 같은 좌표가 여러 번 들어감
- 리스트 복사에서 `copy = original`로 얕은 복사함
- 회전 결과의 행/열 크기를 반대로 둠
- 조건이 `이상`, `초과`, `이하`, `미만`인지 놓침
